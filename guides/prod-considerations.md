# Considerations for production
- Enable [monitoring and alerting](./monitoring-and-alerting.md) and watch the deployments for errors and resource usage. Alerts are [Prometheus Alertmanager](https://prometheus.io/docs/alerting/latest/overview/) rules. Alertmanager is part of the Prometheus chart from that guide. Add the rules to the values file for that Prometheus release, together with the rest of its settings. A file that sets `server.resources` on its own replaces the requests, limits, and volume already installed.
- Enable [Horizontal Pod Autoscalers](https://kubernetes.io/docs/tasks/run-application/horizontal-pod-autoscale/) and [Pod Disruption Budgets](https://kubernetes.io/docs/concepts/workloads/pods/disruptions/#pod-disruption-budgets) where the chart has them. They default to off, except `api.textClassification.hpa`, which defaults to on. DNS and DNSCrypt use the keys `horizonalPodAutoscaler` and `podDisruptionBudget` under `dns.dns` and `dns.dnscrypt`. The other keys are `hpa` and `pdb` on `api`, `dns.clickhoused.internal`, `dns.ipsetd.internal`, and `blockpage`. `frontend`, `categorizer.adminApp`, and `protocolchecker` have `hpa` only. The Postgres operator and the ClickHouse operator create their own disruption budgets.
- Rotate secrets such as `categorizer.adminApp.admin.password` and `api.adminSecret`. Change the value and upgrade the release so the pods roll onto the new environment variable.
- When upgrading a release, compare the generated manifests with the previous ones. The [Helm diff](https://github.com/databus23/helm-diff) plugin does this.
- Put the release in its own namespace with Helm `--namespace`. Resources from this chart land in that namespace. Dashboards and the optional Grafana ingress use `monitoring.namespace` instead, which the monitoring guide sets to `monitoring`.
- When managing multiple deployments, use a different release name and namespace for each. The release name is the prefix on resource names.
- For accounts Safe Surfer manages (`api.accounts.managed` is `false`), set `api.accounts.newAccountPolicy` and `api.accounts.forceEmailOtpOnUnknownIpField`. `newAccountPolicy` is `None`, `VerifyEmail`, `RequireApproval`, or `RequireApprovalAndVerifyEmail`. When accounts are managed, leave `newAccountPolicy` at `None`. `forceEmailOtpOnUnknownIpField` set to `IP` challenges a sign-in from a new IP and does not need an ipinfo provider. `Country`, `Region`, and `City` do, via `api.ipInfoProvider`. The challenge email still needs `api.sendgrid.apiKey`.
- Enable database backups. For an in-cluster database, `db.backups.gcs` and `db.backups.genericS3` in [values.yaml](../charts/safesurfer/values.yaml) each run a `pg_dump` on their own schedule. `genericS3` talks to any S3-compatible endpoint, including AWS, and is rendered only when `db.inCluster.enabled` is true. The Zalando Postgres operator can also upload logical backups when that operator is configured with an S3 bucket. That setup is separate from `db.backups`. ClickHouse has no backup job in this chart. When `clickhouse.internal.persistence.enabled` is true, snapshot that volume.
